# Tavily 웹 검색 연동 계획서

Tavily Search API 를 **웹 검색 전용**으로 붙여 Book Brief 를 모델의 기억이 아니라
**실제로 읽은 페이지**로 채운다. 무료 등급 **월 1,000 크레딧** 안에서 쓴다.

---

## 1. 왜 필요한가 — 오늘 측정한 것

PR #30 을 조사하다 확인한 사실이다. 같은 책·같은 프롬프트로 두 모델에 물었다.

**『움푹산의 비밀』(천희순, 크레용하우스)** — 서지 조회로 제목·지은이·출판사·ISBN·출판사
책소개 403자까지 **확인된** 책이다.

| 모델 | 응답 |
| --- | --- |
| `gemini-3.6-flash` | 모든 항목을 비워 반환 → `brief` NULL → 문제를 만들 수 없음 |
| `gemini-3-flash-preview` | 줄거리 404자 · 등장인물 4명 · 사건 8개를 **통째로 지어냄** |

지어낸 쪽의 실제 응답이다.

> 동구는 아빠의 사업 실패로 시골 할아버지 댁으로 이사한다… 움푹산을 깎아 **골프장**을
> 건설하려는 회사… 멸종된 줄 알았던 **한국 표범** 가족…

실제 책은 **거인 크네**가 움푹산의 아이들을 구하는 이야기다. 전부 없는 내용인데
`found: true`, `readyForQuiz: true` 로 통과했다.

**여기가 핵심이다.** 근거 검사(`services/grounding.ts`)는 문항의 근거를 **Brief 와 대조**한다.
Brief 자체가 날조되면 그 검사는 날조를 "근거 있음" 으로 **인정한다.**

```
모델 기억 → 날조된 Brief → 근거 검사 통과 → 틀린 내용이 근거까지 갖춘 문항
```

### 프롬프트로는 못 막는다는 것도 측정했다

PR #30 에서 검증된 출판사 책소개를 조사 프롬프트에 넣고 "기억이 이것과 어긋나면 비워라" 고
지시했다. 결과는 **개선되었지만 부족하다.**

| | 조치 전 | 조치 후 |
| --- | --- | --- |
| `gemini-3-flash-preview` | 동구 · 한국 표범 · 골프장 (**다른 책**) | 거인 크네 (**맞는 책**) — 그러나 산사태·폭우 등 **세부는 여전히 지어냄** |
| `gemini-3.6-flash` | 빈손 | **여전히 빈손** |

책소개 403자는 **책을 특정하는 데는 충분하지만 줄거리를 대신하지 못한다.** PR #28 에서
이미 같은 결론에 도달했다 — 근거부족 탈락률과 라운드 수는 서지 API 로 풀 문제가 아니라
**웹 검색 그라운딩의 몫**이라고 적어 두었다. 그 웹 검색이 지금 막혀 있다.

| 경로 | 상태 |
| --- | --- |
| Gemini Google 검색 그라운딩 | 무료 등급에서 429 |
| Cloudflare Worker → Gemini | 홍콩 콜로 지역 차단 (그래서 브라우저 릴레이를 쓴다) |
| OpenAI `web_search` | 쓸 수 있으나 유료 키가 필요하고 검색 비용이 토큰에 섞여 보이지 않는다 |

**Tavily 는 이 셋과 무관한 독립 경로다.** 서버가 직접 부르고, 크레딧이 눈에 보이고,
어떤 AI 제공자를 쓰든 똑같이 동작한다.

## 2. 확인한 사실 (2026-08-18, 공식 문서)

| 항목 | 값 | 출처 |
| --- | --- | --- |
| 무료 등급 | **월 1,000 크레딧**, 신용카드 불필요 | `docs.tavily.com/documentation/api-credits` |
| `search_depth: basic` | **1 크레딧 / 요청** | 같은 문서 |
| `search_depth: advanced` | **2 크레딧 / 요청** | 같은 문서 |
| `include_raw_content` | **추가 과금 없음** | 같은 문서 |
| `max_results` | 0–20, 기본 5. **결과 수는 과금과 무관** | API 레퍼런스 |
| `chunks_per_source` | 1–3 (advanced 에서만 의미) | API 레퍼런스 |
| 레이트리밋 (개발/무료) | **100 RPM** | `docs.tavily.com/documentation/rate-limits` |

**과금은 요청 수 × 깊이로만 결정된다.** 결과를 20건 받든 5건 받든, 원문을 통째로 받든
크레딧은 같다. 이 사실이 아래 설계를 결정한다.

### 아직 확인 못 한 것 — Phase 0 에서 낸다

`네이버 책 검색을 401 응답만 보고 "살아 있다" 고 적을 뻔했던` 일을 되풀이하지 않는다.
문서만으로 단정할 수 없는 것을 명시해 둔다.

| 미확인 | 왜 중요한가 | 어떻게 확인하나 |
| --- | --- | --- |
| **한국 아동서 커버리지** | 이 연동의 전부다. 『움푹산의 비밀』 같은 책의 독후감·서평이 색인돼 있는가 | Phase 0 에서 알려진 책 3권 + 안 알려진 책 3권으로 직접 호출 |
| **Cloudflare 홍콩 콜로에서 접근 가능한가** | Gemini 가 막힌 바로 그 이유 | 배포 환경에서 실제 호출 |
| **`raw_content` 의 실제 분량과 품질** | 프롬프트 예산과 직결 | 응답 바이트를 재서 기록 |
| **크레딧 차감이 문서대로인가** | 예산 계산의 전제 | 대시보드 잔량을 호출 전후로 비교 |

## 3. 크레딧 산수 — 이것이 설계를 결정한다

월 1,000 크레딧을 **책 몇 권**으로 바꿀 수 있는지가 유일한 제약이다.

| 방식 | 책 1권당 | 월 처리 가능 |
| --- | --- | --- |
| basic 1회 | 1 크레딧 | **1,000권** |
| advanced 1회 | 2 크레딧 | **500권** |
| advanced 2회 (줄거리 / 서평 분리) | 4 크레딧 | 250권 |
| basic 3회 (질의 다변화) | 3 크레딧 | 333권 |

**결론: advanced 1회 + `max_results` 를 크게 + `include_raw_content`.**

결과 수와 원문이 공짜이므로, **질의를 여러 번 쪼개는 것보다 한 번을 깊게 하는 것이 싸다.**
질의를 3개로 쪼개면 크레딧이 3배인데, `max_results` 를 5→20 으로 올리는 것은 0배다.

```
쓰지 않을 방식:  "줄거리" 검색 + "등장인물" 검색 + "독후감" 검색   → 3~6 크레딧
쓸 방식:        한 질의, advanced, max_results=20, raw_content   → 2 크레딧
```

500권/월이면 부모 한 사람 기준으로는 충분하다. **다만 부모가 늘면 이 숫자가 먼저 바닥난다.**
그래서 §4.4 예산 가드가 선택이 아니라 필수다.

## 4. 설계

### 4.1 키는 서비스 공용 — 부모별이 아니다

알라딘·카카오와 같다. `wrangler secret put TAVILY_API_KEY`.

AI 키는 부모별인데(§24) 검색 키는 공용인 이유: **크레딧이 서비스 전체의 공유 자원**이고,
부모에게 "Tavily 계정을 만드세요" 라고 요구할 수 없다. 대신 그 공유 자원을 §4.4 로 지킨다.

키가 없으면 **조용히 건너뛴다.** 지금 동작에 영향이 없어야 한다 — 알라딘을 붙일 때와 같은 규칙.

### 4.2 어디에 꽂히는가

```
        지금                                    바뀐 뒤
  ┌──────────────┐                        ┌──────────────┐
  │ 서지 API 조회 │  제목·저자·책소개        │ 서지 API 조회 │
  └──────┬───────┘                        └──────┬───────┘
         │                                       │
         │                                ┌──────▼───────┐
         │                                │  Tavily 검색  │  ← 새로 붙는 것
         │                                └──────┬───────┘  줄거리·서평 원문
         │                                       │
  ┌──────▼───────┐                        ┌──────▼───────┐
  │  AI 조사      │ 기억으로 채움           │  AI 조사      │ 받은 자료 안에서만 정리
  └──────┬───────┘                        └──────┬───────┘
  ┌──────▼───────┐                        ┌──────▼───────┐
  │  Book Brief   │                       │  Book Brief   │ [웹 자료] 절이 생김
  └───────────────┘                       └───────────────┘
```

새 모듈 `src/search/tavily.ts` 하나. `src/search/bibliographic.ts` 와 같은 층이고
같은 규칙을 따른다 — 키 없으면 건너뛰고, 실패해도 조사 전체를 무산시키지 않는다.

`prepareBib` 가 `bib_cache` 를 쓰는 것과 **똑같이** `prepareWeb` 이 `web_cache` 를 쓴다.
준비 단계가 받은 것을 반영 단계가 그대로 읽어야 **프롬프트가 본 자료와 저장되는 출처가
같아진다.** 두 번 부르면 크레딧도 두 배고 내용도 갈린다.

### 4.3 질의를 어떻게 만드는가

```
"{제목}" {지은이} 줄거리 등장인물 독후감
```

옵션:

| 옵션 | 값 | 이유 |
| --- | --- | --- |
| `search_depth` | `advanced` | 페이지에서 관련 구간을 뽑아 준다. 2 크레딧의 값 |
| `max_results` | `20` | 공짜다. 한국 아동서는 상위 5건이 서점 판매 페이지로 채워질 수 있다 |
| `include_raw_content` | `"markdown"` | 공짜다. 독후감 블로그의 줄거리는 본문에 있다 |
| `chunks_per_source` | `3` | 공짜다 |
| `country` | `"KR"` | 한국 페이지를 올린다 |
| `topic` | `general` | `news` 는 이 용도에 맞지 않는다 |
| `exclude_domains` | 판매 페이지 일부 | Phase 0 측정 후 정한다. 미리 넣지 않는다 |

**`include_answer` 는 쓰지 않는다.** Tavily 가 요약하면 그 요약이 또 하나의 기억이 된다.
우리는 **원문**이 필요하다 — 근거 검사가 대조할 대상이기 때문이다.

### 4.4 예산 가드 — 없으면 안 된다

월 1,000 은 조용히 넘길 수 있는 숫자다. **KV 카운터로 막는다.**

```
키:     tavily:2026-08          (KST 기준 월)
값:     지금까지 쓴 크레딧
상한:   950                     ← 1,000 이 아니다
```

50 을 남기는 이유: 개발·확인용으로 몇 번 부르게 되는데, 그것이 부모의 조사를 굶기면 안 된다.

호출 **전에** 올리고(초과분을 나중에 발견하면 늦다), 상한에 닿으면 **검색을 건너뛴 채
조사를 계속한다.** 실패시키지 않는다 — 지금 동작이 그대로 남을 뿐이다. 부모에게는
`searchNotice` 로 알린다.

```
"이달 웹 검색 한도를 다 썼습니다. 모델이 아는 지식으로 정리했으니 내용을 꼭 확인해 주세요."
```

### 4.5 캐시 — 크레딧을 지키는 두 번째 장치

`books.web_cache` 컬럼(마이그레이션 0010)에 검색 결과를 적어 둔다.

| 상황 | 동작 |
| --- | --- |
| 처음 조사 | 검색 → 캐시 기록 (2 크레딧) |
| **정보 다시 찾기** | 캐시 재사용 (**0 크레딧**) — 부모가 명시적으로 "새로 검색" 을 누르면 그때만 재검색 |
| **재도전 회차 생성** | 캐시 재사용 (0 크레딧) |
| 제목·지은이를 고친 뒤 | 캐시 무효화 — 다른 책일 수 있다 |

**재도전이 크레딧을 먹으면 안 된다.** 아이가 5번 재도전하면 문제를 5번 만들지만
책은 그대로다.

### 4.6 출처 기록

Tavily 결과는 `book_sources` 에 `source: "web"` 으로 들어간다 — 이미 있는 종류다.
`url`, `title`, 그리고 발췌를 `MAX_SOURCE_CONTENT`(2,000자) 로 잘라 넣는다.

`raw_content` 는 **저장하지 않는다.** 원문 전체를 쌓아 두는 것은 §6 이 금지하고,
분량도 예측할 수 없다. 프롬프트에 넣을 때도 소스당 상한을 건다(§5.2).

이로써 `evidenceWeak`(웹 출처 2건 미만) 기준이 **처음으로 실제 의미를 갖는다.**
지금은 알라딘·카카오로 억지로 채우고 있다.

## 5. 출제 규칙 강화 — 이 자료가 생겨야 할 수 있는 것

오늘 얻은 교훈은 분명하다. **프롬프트로 부탁하는 것은 지켜지지 않는다.** 책소개를 주고
"어긋나면 비워라" 고 했는데도 모델은 세부를 지어냈다. 그래서 강화는 **기계적인 것**을
중심으로 하고, 프롬프트는 보조로 둔다.

### 5.1 근거 검사를 **웹 자료 기준**으로 좁힌다 ← 가장 중요

지금 `checkGrounding` 은 문항의 `evidence` 를 **Brief 전체**와 대조한다. Brief 에는
모델이 기억으로 쓴 `[줄거리]` 도 들어 있으므로, 모델은 **자기가 지어낸 줄거리를 근거로
자기 문항을 정당화**할 수 있다. 오늘 본 그대로다.

```
지금:   evidence  vs  Brief 전체 (모델 기억 포함)      ← 자기 참조
바꿈:   evidence  vs  [웹 자료] + [줄거리]            ← 웹 자료가 있을 때
```

**웹 자료가 확보된 책에 한해** 근거 대조 대상에서 `[소개]`·`[출판사 소개]` 를 빼고,
`[웹 자료]` 를 넣는다. 웹 자료가 없으면 지금 규칙 그대로 — 갑자기 모든 책이 못 만들어지면 안 된다.

임계값(`MIN_EVIDENCE_GROUNDING = 0.65`)은 **건드리지 않는다.** PR #28 실측에서 통과한
50문항 전부가 1.00 이었다. 임계값이 문제였던 적이 없다.

### 5.2 조사 프롬프트를 "요약" 에서 "발췌" 로 바꾼다

지금 지시는 "당신이 아는 지식으로 정리하세요" 다. 웹 자료가 있으면 지시가 달라져야 한다.

```
- 아래 [웹 자료] 안에 **적혀 있는 것만** 정리하세요.
- 자료에 없는 사건·인물·결말을 기억으로 채우지 마세요. 자료가 다루지 않은 항목은 비웁니다.
- plotSummary 의 각 문장은 자료 어느 대목에서 나왔는지 말할 수 있어야 합니다.
```

소스당 프롬프트 투입 상한을 둔다(제안: 소스당 1,500자 × 상위 6건 ≈ 9,000자).
`raw_content` 를 통째로 넣으면 프롬프트가 수만 자가 되어 비용과 지연이 커지고,
모델이 중간을 흘린다.

### 5.3 검증 기준에 "자료에서 확인 가능한가" 를 넣는다

`src/ai/validate.ts` 의 10번 기준은 지금 "제공된 책 정보에 적혀 있는 내용인가" 다.
웹 자료가 있으면 더 좁힌다 — **`[웹 자료]` 또는 `[줄거리]` 에서 확인되는가.**
`[소개]`·`[출판사 소개]` 만으로 확인되는 문항은 §7 위반으로 탈락(이미 있는 규칙).

### 5.4 §7 은 그대로 둔다

`[출판사 소개]` 는 배경이지 출제 근거가 아니다. PR #28 실측에서 50/50 이 지켜졌고,
홍보 문구로 문제를 만들면 책을 읽지 않아도 풀린다. **웹 자료가 생겼다고 이 규칙을 풀 이유가 없다.**

### 5.5 하지 않을 것

`isReadyForQuiz` 를 "웹 근거가 있어야 함" 으로 조이는 것은 **하지 않는다.** 지금 잘 되는
책들이 갑자기 잠긴다. 근거의 강약은 `evidenceWeak` 로 알리고 최종 판단은 검수하는 부모가
한다(§11) — 이미 정한 원칙이다.

## 6. 측정 — 되었는지 어떻게 아는가

기준선은 오늘 값이다. 같은 책으로 전후를 비교한다.

| 지표 | 지금 | 목표 |
| --- | --- | --- |
| 『움푹산의 비밀』 `found` | **false** (3.6-flash) | true |
| 같은 책, 지어낸 세부 | 산사태·폭우 등 (3-flash-preview) | 자료에서 확인되는 내용만 |
| 웹 출처(`source: "web"`) | **0건** | 2건 이상 |
| `evidenceWeak` | 알라딘·카카오로 억지 충족 | 실제 웹 근거로 충족 |
| 1라운드 근거부족 탈락 | 평균 1.0 / 10 (PR #28, n=5) | 0.5 이하 |
| 목표까지 라운드 | 평균 1.6 → 여유분 적용 후 1.0~2.0 | 1.0 |
| 책 1권당 크레딧 | — | **2 (캐시 적중 시 0)** |

**날조 검출은 사람이 봐야 한다.** 잘 아는 책 3권으로 생성된 문항을 직접 읽고 사실 여부를
센다. 자동화할 수 있는 지표가 아니다 — 자동으로 잴 수 있었다면 애초에 막을 수 있었다.

## 7. Phase 계획

### Phase 0 — 발급과 확인 ✅ (2026-08-18)

**판정: GO.** 한국책 커버리지가 좋고, AI 가 모르던 책의 자료를 실제로 찾아냈다.

`api.tavily.com` 은 살아 있다 — 대조군으로 확인했다(가짜 키 401, 없는 경로 404, 정상 200).
`country` 는 국가 **코드가 아니라 이름**이다(`"KR"` 은 400, `"south korea"` 가 맞다).

#### 커버리지 (basic, `max_results: 20`)

정답 낱말은 **책을 읽지 않으면 쓸 수 없는 말**로 골랐다(등장인물 이름·고유 사건).
판매 페이지 홍보 문구에는 나오지 않는다.

| 책 | 등급 | 줄거리 담긴 결과 | 정답 낱말 |
| --- | --- | --- | --- |
| 마당을 나온 암탉 | 널리 알려짐 | 10 / 19 | 잎싹·초록머리·족제비·양계장 **4/4** |
| 몽실 언니 | 널리 알려짐 | 8 / 20 | 몽실·난남·댓골·새어머니 **4/4** |
| 나쁜 어린이 표 | 널리 알려짐 | 12 / 19 | 건우·나쁜 어린이 표·선생님·스티커 **4/4** |
| 우등생 바이러스 | 덜 알려짐 | 13 / 20 | 우등생·바이러스·전학 **3/3** |
| **움푹산의 비밀** | **거의 안 알려짐** | **5 / 20** | **크네·거인·움푹산 3/3** |
| Dirty Bertie PONG! | 영어책 | 2 / 20 | Bertie·Eugene 2/4 |

**가장 중요한 줄은 『움푹산의 비밀』이다.** AI 가 모른다고 했고, 다른 모델은 그 자리를 날조로
채웠던 그 책의 **"거인 크네" 이야기가 웹에는 있었다.** 네이버 블로그 서평·별밤서재·교보문고에서
나왔다. 우리가 못 찾은 것이 아니라 **찾아본 적이 없었을 뿐이다.**

#### basic 이 advanced 와 같았다

| 책 | basic | advanced |
| --- | --- | --- |
| 마당을 나온 암탉 | 10 | 11 |
| 몽실 언니 | 8 | 8 |
| 나쁜 어린이 표 | **12** | 8 |
| 우등생 바이러스 | 13 | 13 |
| 움푹산의 비밀 | 5 | 5 |

**2 크레딧이 값을 하지 않는다.** `include_raw_content` 로 페이지 전문을 받기 때문에
advanced 의 구간 추출이 더 줄 것이 없다. 그래서 기본을 basic 으로 둔다.

#### 깊이만 올리는 재시도는 쓸모없다 — 질의를 넓혀야 한다

"내용이 부족할 때 advanced 로" 를 그대로 재면 이렇다.

| 책 | basic | advanced (같은 질의) | advanced (넓힌 질의) |
| --- | --- | --- | --- |
| 움푹산의 비밀 | 관련 9건 | 9건 | **12건** |
| 바나나가 뿔났다 | 0건 | **0건** | **1건** |
| (없는 책) | 0건 | 0건 | 0건 |

**깊이만 올리면 0 → 0 이다.** 좁은 질의(`"제목" 저자 줄거리 등장인물 독후감`)가 자료 없는
책에서는 오히려 아무것도 못 찾기 때문이다. 그래서 두 번째 시도는 **advanced + 넓힌 질의**로 간다.

#### 영어책은 이 연동의 몫이 아니다

한국어 낱말을 붙여 영어책을 물으면 **`health.kr` 이 20건 중 8건**을 차지했다. 영어 질의로
바꾸니 그 오염은 사라졌지만 줄거리 담긴 결과는 2/20 에 그쳤다. 영어 아동 시리즈물은 웹에
편별 줄거리가 없다. **질의는 언어에 맞추되, 이 연동의 이득은 한국책에 있다고 적어 둔다.**

#### "부족" 의 판정 기준을 실측으로 정했다

부피는 신호가 못 된다 — **없는 책도 결과 19건, 원문 3,332자**가 온다. 유일한 신호는
**그 결과가 이 책을 다루는가**다. `groundedRatio` (근거 검사·판본 매칭이 이미 쓰는 계산)로
제목 일치도 0.8 이상인 결과를 셌다.

| 마당을 나온 암탉 | 우등생 바이러스 | 움푹산의 비밀 | Dirty Bertie | 바나나가 뿔났다 | 없는 책 |
| --- | --- | --- | --- | --- | --- |
| 20 | 12 | 9 | 6 | **0** | **0** |

실제 책 6건 이상, 자료 없는 책 0건. **5건을 문턱으로 둔다.**

> 단순 문자열 포함으로 셌을 때는 『Dirty Bertie PONG!』이 0 이었다 — 페이지는
> "Dirty Bertie: Pong!" 으로 쓴다. 어간 대조가 그것을 넘는다. 같은 계산을 네 번째로
> 구현하지 않은 것이 여기서 값을 했다.

#### 크레딧

문서대로다. basic 1, advanced 2. Phase 0 전체가 약 60 크레딧을 썼다.

### Phase 0 — 발급과 확인 (원안)

1. `tavily.com` 가입 → API 키 발급 (신용카드 불필요). `.env` 에 `TAVILY_API_KEY` 추가
2. **커버리지 측정** — 알려진 책 3권(마당을 나온 암탉 / 나쁜 어린이표 / 몽실 언니) +
   안 알려진 책 3권(움푹산의 비밀 포함)으로 직접 호출. 각각 기록한다:
   - 결과 건수, 도메인 분포, 줄거리를 담은 결과가 몇 건인지
   - `raw_content` 바이트, 실제 크레딧 차감량
3. **홍콩 콜로 접근성** — 배포 환경에 임시 경로 없이, `wrangler dev --remote` 로 확인
4. `basic` 과 `advanced` 를 같은 질의로 비교해 **2 크레딧이 값을 하는지** 판단

> **Phase 0 에서 커버리지가 나쁘면 여기서 멈춘다.** 크레딧을 쓰는 구조를 먼저 만들어 놓고
> 자료가 없다는 것을 나중에 아는 것이 가장 나쁘다. 서지 API 때 배운 것이다.

### Phase 1 — 어댑터와 예산 가드 ✅ (2026-08-18)

- `src/search/tavily.ts` — basic 우선, 관련 결과 5건 미만이면 **advanced + 넓힌 질의**로 한 번 더
- `src/services/search-budget.ts` — 월 KV 카운터, 상한 950, **호출 전에** 잡는다
- 마이그레이션 `0010_web_search.sql` — `web_cache`, `web_searches`
- `prepareWeb` / `refreshWeb` — 캐시 재사용, 책당 6회(첫 조사 1 + 재검색 5)
- `POST /api/books/:id/web-search` + 화면의 **웹 자료 다시 찾기** 버튼(남은 횟수·크레딧 표시)
- 찾은 자료를 **참고 자료에 바로 넣는다**

실측(로컬, 실제 API):

```
검색 전   참고 자료 0건 · 남은 재검색 6회 · 남은 크레딧 950
검색 후   찾은 자료 20건 · 남은 5회 · 크레딧 949   ← basic 1 크레딧
다시 열기 참고 자료 20건 (네이버 블로그·별밤서재·교보문고·도서관)
6회 소진  → 거절. 크레딧은 정확히 6 만 줄었다
```

> **원안에서 벗어난 것**: 계획은 Phase 1 을 "어댑터와 가드" 로만 두고 참고 자료 적재를
> Phase 2 로 미뤘다. 그대로 하면 Phase 1 이 크레딧만 쓰고 부모에게 아무것도 보여주지
> 못한다 — 실제로 처음 돌렸을 때 "20건 찾았습니다" 를 보고 목록은 0건인 화면이 나왔다.
> 참고 자료 적재를 Phase 1 로 당겼다. Brief·프롬프트·근거 검사는 Phase 2·3 그대로다.

### Phase 1 — 어댑터와 예산 가드 (원안)

- `src/search/tavily.ts` — 호출, 정규화, 실패 시 빈 배열
- KV 예산 카운터(§4.4) — **어댑터보다 먼저 동작해야 한다**
- 마이그레이션 `0010_web_cache.sql`
- `prepareWeb` / 캐시 재사용(§4.5)
- 키가 없으면 지금과 완전히 동일하게 동작하는 것을 테스트로 고정

### Phase 2 — Brief 와 조사 프롬프트

- Brief 에 `[웹 자료]` 절 (소스당 상한 적용)
- 조사 지시를 "발췌" 로 교체(§5.2)
- `book_sources` 에 `source: "web"` 적재
- 『움푹산의 비밀』이 `found: true` 가 되는지 확인

### Phase 3 — 출제 규칙 강화

- `checkGrounding` 의 대조 범위를 웹 자료 기준으로(§5.1)
- `validate.ts` 10번 기준 강화(§5.3)
- 웹 자료가 없는 책은 지금 규칙 그대로인 것을 테스트로 고정

### Phase 4 — 실측과 조정

- §6 표를 채운다. 조사는 한 번만 하고 생성만 반복해 크레딧을 아낀다
- 잘 아는 책 3권의 문항을 직접 읽고 날조 여부를 센다
- 크레딧 실사용량으로 §3 산수를 재검증한다

## 9-1. 원안에 적어 둔 결정 항목

1. **Phase 0 결과가 애매하면 어떻게 하나.** 커버리지가 "알려진 책은 좋고 안 알려진 책은
   나쁨" 으로 나올 가능성이 높다. 그 경우에도 붙일 값어치가 있다고 본다 — 알려진 책의
   날조를 막는 것만으로도 §1 의 문제가 절반은 풀린다. 다만 **부모 직접 입력(PR #30)이
   여전히 안 알려진 책의 유일한 길**로 남는다.
2. **재검색 버튼을 부모에게 노출할 것인가.** 크레딧을 쓰는 유일한 사용자 조작이 된다.
   노출하되 "이달 남은 검색 N회" 를 함께 보여 주는 쪽을 제안한다.
3. **advanced 냐 basic 이냐** — Phase 0 의 4번으로 정한다. 미리 정하지 않는다.
